Welcome to Recon Forge, a governed policy evolution application for transaction reconciliation. It compares internal ledger records with processor settlements, identifies unmatched transactions, and helps operators improve matching rules using measured evidence. This demonstration uses synthetic data with four familiar processor labels: Stripe, Adyen, PayPal, and Square. The dashboard shows ingestion progress, open breaks, the active policy, and accuracy measured on a fixed historical benchmark.

The policy history view makes every change traceable. Here, approved versions have increased benchmark accuracy from twenty to forty percent. Each processor has explicit settings for amount tolerance, settlement timing, fixed fees, and percentage fees. Diagnosis identifies recurring failures, analysis checks evidence and verified memories, and evolution proposes a bounded change. The agent follows its policy skill and rules, changing one supported parameter at a time.

Human approval is the control point before a candidate becomes active. The review view compares current live accuracy with the active and candidate backtest results. A compact diff highlights the affected parameter, with red for the previous value, green for the proposed value, and line numbers for context. Clicking approve records the decision first. A persistent confirmation then tracks the next steps, so operators can see that their decision was saved.

The workflow view explains what happens after approval. Promotion activates the eligible policy, replay checks it against held out data, and verified learning is saved for future incidents. Four visible progress stages distinguish queued work, active processing, and completion. If replay fails its safety checks, the application can roll back the candidate. Data ingestion runs independently of this workflow, so transactions can keep arriving while a policy is being reviewed or verified.

Backtesting measures improvement before a change reaches the active policy. The independent historical benchmark contains eight thousand pairs, while the live stream has been extended to twenty five thousand. The synthetic scenarios include settlement delays, fee differences, amount drift, reference errors, and duplicate allocation ambiguity. Guardrails check false matches, regressions, and improvement. Candidate backtest accuracy is a projection for that candidate; it becomes an active result only after approval and successful verification.

The reconciliation view connects policy evolution to operational outcomes: matched transactions, outstanding amounts, processor summaries, and unresolved cases. Long term Mongo database storage retains policy versions, human decisions, evaluation results, verified memories, and audit history. Raw demo fixtures remain local, and routine telemetry expires automatically. Python code and fuzzy reference evolution are reserved for a later stage. Recon Forge demonstrates a controlled learning loop: observe failures, propose a small change, measure it, approve it, and verify the outcome.
